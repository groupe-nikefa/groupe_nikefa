# Project Analysis: GROUPE NIKEFA — Medical Supply Marketplace

## Project Structure Summary

The project is a Flutter mobile app (3.24.0+ / Dart 3.5.0+) built with:

| Layer | Technology |
|---|---|
| State Management | Riverpod 2.6.1 (StateNotifier, StreamProvider, FutureProvider) |
| Routing | GoRouter 14.2.0 with ShellRoute-based bottom navigation |
| Backend/Auth | Supabase (supabase_flutter 2.5.7) |
| Local Cache | Hive + Hive Flutter (offline product/category browsing) |
| Connectivity | connectivity_plus 6.0.5 |
| Images | cached_network_image, image_picker, flutter_image_compress |
| Localization | flutter_localizations + custom AppLocalizations (ar/fr) |
| Notifications | flutter_local_notifications 18.0.0 for order status updates |

## Top Bugs & Issues (Prioritized)

### 1. CRITICAL — Double Supabase Initialization Causes App Crash
**Files:** `main.dart:31` + `startup_validation.dart:42`
`initializeSupabase()` is called in `main()` AND again inside `StartupValidation._validate()`. Supabase throws on the second call. The `StartupValidation` widget wraps the entire app in `MaterialApp.router`'s `builder`, so both calls execute every launch. The second call will crash with an unhandled exception since `Supabase.initialize()` can only be called once.

### 2. HIGH — Currency Inconsistency: DZD vs FCFA
**File:** `checkout_screen.dart:427-486` vs `home_screen.dart:291`, `catalog_screen.dart:357`
Products display prices as "DZD" (Algerian Dinar) in the home screen, catalog, and product detail. But the checkout flow (order review step and total calculations) displays "FCFA" (Central African CFA Franc). This discrepancy will confuse users and is likely incorrect — the app uses one currency for display and another at the payment stage.

### 3. HIGH — Guest Cart Is Not Reactive (State Management Flaw)
**File:** `cart_provider.dart:36-38`
`cartItemsProvider` for guest mode returns `Stream.value(repository.getGuestCartItems())` — a one-shot emission. When a guest adds, updates, or removes cart items, the `cartItemsProvider` and `cartCountProvider` do NOT re-emit updated values. The UI will not reflect changes reactively for guest users. Switching from `Stream.value(...)` to a proper Hive `watch()`/listenable stream or a `StateNotifier` is needed.

### 4. MEDIUM — `cancelOrderProvider` Creates Duplicate State Instance
**File:** `order_provider.dart:141-145`
`cancelOrderProvider` instantiates a separate `CreateOrderNotifier`, decoupled from `createOrderProvider`. Calling `cancelOrder()` on one notifier has no visible effect on `createOrderProvider.state`. Loading/error state changes for cancellation are isolated and invisible to consumers watching `createOrderProvider`.

### 5. MEDIUM — Deprecated `StateNotifier` Usage (Riverpod 2.x)
**Files:** `cart_provider.dart:87`, `catalog_providers.dart:109`, `order_provider.dart:81`, `admin_providers.dart:87+136+158`
Multiple notifiers extend `StateNotifier` which is deprecated in the Riverpod 2.x version used by this project. They should be migrated to `Notifier` / `AsyncNotifier` to avoid runtime warnings and ensure compatibility with future Riverpod versions.

### 6. MEDIUM — Nested MaterialApp in StartupValidation
**File:** `startup_validation.dart:73,94` + `main.dart:92-101`
`StartupValidation` creates its own `MaterialApp` for loading/error screens, nested inside `NikefaApp`'s `MaterialApp.router`. This creates two `MaterialApp` widgets in the widget tree, duplicating theme, localization delegates, and navigator contexts. The loading/error screens lose access to the parent's theme and locale settings entirely.

### 7. LOW — `dart:io` Import in Admin Providers Breaks Web Compatibility
**File:** `admin_providers.dart:1`
Uses `import 'dart:io';` for `File` type in `ProductFormNotifier.createProduct()`. This makes the admin feature incompatible with Flutter Web (where `dart:io` is unavailable). Should use `cross_file` or a platform-agnostic abstraction.

### 8. LOW — Test File Cannot Run Without Full Initialization
**File:** `test/widget_test.dart:10`
The smoke test calls `pumpWidget(const ProviderScope(child: NikefaApp()))` without initializing Hive, Supabase, or dotenv (which are done in the actual `main()` function). The test will crash on `dotenv.env` access or Supabase client calls.

### 9. LOW — `Env` Reads from `dotenv.env` Before `dotenv.load()` in Widget Test
**File:** `core/constants/env.dart:5`
`Env.supabaseUrl` reads `dotenv.env['SUPABASE_URL']` eagerly. If accessed before `dotenv.load()` completes, it returns the placeholder value. While production code handles this timing (via `main()` calling `dotenv.load()` first), this is untestable without mocking `dotenv`.

### 10. NOTE — `isOfflineProvider` Cross-File Reference
**File:** `catalog_screen.dart:97` references `isOfflineProvider` defined in `app_router.dart:39`  
While functionally correct (it's a global provider), this couples the catalog screen to the router file. Better to move `isOfflineProvider` to a shared location (e.g., `core/providers/connectivity_provider.dart`).

## Analysis Notes
- **No obvious syntax errors** — the code compiles structurally from what can be statically analyzed
- **Hive adapters are manual** — no `hive_generator` code generation was used; adapters are correctly hand-written
- **Auth flow** is well-structured with Supabase session management, retry logic for profile creation, and proper error mapping
- **Realtime subscriptions** are implemented for products, categories, cart items, and orders via Supabase streams
- **Repository pattern** is cleanly separated from UI with Riverpod providers bridging the layers
- **Localization** supports Arabic (RTL) and French (LTR) with custom AppLocalizations delegates
